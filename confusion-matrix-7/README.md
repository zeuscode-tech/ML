# Матрица ошибок — вариант № 7

**Основной уровень (пункты 1–6).**

Сценарий: камера фиксации проезда на красный. Положительный класс («да») — нарушение было. Метрики округлены до трёх знаков; расчёты выполнены без промежуточного округления.

## 1. Исходная матрица ошибок

Строки — фактический класс, столбцы — прогноз камеры.

| Факт / Прогноз | Нарушение есть («да») | Нарушения нет («нет») |
|---|---:|---:|
| Нарушение было | TP = 39 | FN = 11 |
| Нарушения не было | FP = 30 | TN = 170 |

Всего: N = 39 + 11 + 30 + 170 = 250 случаев. Реальных нарушений — 50, случаев без нарушения — 200.

## 2. Значение четырёх ячеек

- **TP = 39:** нарушение действительно было, камера правильно его обнаружила.
- **FN = 11:** нарушение было, но камера его пропустила.
- **FP = 30:** нарушения не было, но камера ошибочно зафиксировала его.
- **TN = 170:** нарушения не было, камера правильно определила его отсутствие.

## 3. Расчёт метрик

**Accuracy — доля правильных решений среди всех случаев:**

$$\mathrm{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN}=\frac{39+170}{250}=0{,}836.$$

Камера правильно классифицировала 83,6% случаев.

**Precision — доля реальных нарушений среди срабатываний камеры:**

$$\mathrm{Precision}=\frac{TP}{TP+FP}=\frac{39}{39+30}=\frac{39}{69}\approx0{,}565.$$

Около 56,5% срабатываний соответствуют реальным нарушениям.

**Recall — доля обнаруженных нарушений среди всех реальных нарушений:**

$$\mathrm{Recall}=\frac{TP}{TP+FN}=\frac{39}{39+11}=\frac{39}{50}=0{,}780.$$

Камера обнаружила 78% реальных нарушений.

**Specificity — доля правильно распознанных случаев без нарушения:**

$$\mathrm{Specificity}=\frac{TN}{TN+FP}=\frac{170}{170+30}=\frac{170}{200}=0{,}850.$$

В 85% случаев без нарушения камера правильно не сработала.

**F1 — гармоническое среднее precision и recall:**

$$F_1=\frac{2\cdot\mathrm{Precision}\cdot\mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}=\frac{2TP}{2TP+FP+FN}=\frac{78}{78+30+11}=\frac{78}{119}\approx0{,}655.$$

## 4. Сравнение с моделью, которая всегда отвечает «нет»

Такая модель правильно распознаёт все 200 случаев без нарушения, но пропускает все 50 нарушений.

$$\mathrm{Accuracy}_{\text{всегда «нет»}}=\frac{200}{250}=0{,}800.$$

Accuracy камеры равна 0,836, а постоянной модели — 0,800. Разница составляет 0,036, или 3,6 процентного пункта.

Одной accuracy в этом сценарии недостаточно: 80% объектов относятся к отрицательному классу. Поэтому даже модель, которая не обнаруживает ни одного нарушения, получает accuracy 0,800. Нужно также учитывать precision и recall: сколько обвинений обоснованны и сколько нарушений найдено.

## 5. Стоимость ошибок и приоритетная метрика

При условии автоматического назначения штрафов более дорогой считаю ошибку **FP**: невиновный водитель получает необоснованный штраф и вынужден тратить время на его оспаривание. Такие ошибки также снижают доверие к системе, поэтому приоритет — максимизировать **precision**, сохраняя приемлемый recall. Ошибки FN тоже существенны, поскольку реальные нарушения остаются незамеченными; выбор приоритета зависит от способа использования камеры.

## 6. Снижение порога классификации

По условию 9 объектов переходят из FN в TP, а 19 — из TN в FP:

- TP = 39 + 9 = 48;
- FN = 11 − 9 = 2;
- FP = 30 + 19 = 49;
- TN = 170 − 19 = 151.

### Новая матрица

| Факт / Прогноз | Нарушение есть («да») | Нарушения нет («нет») |
|---|---:|---:|
| Нарушение было | TP = 48 | FN = 2 |
| Нарушения не было | FP = 49 | TN = 151 |

Число объектов не изменилось: 48 + 2 + 49 + 151 = 250.

### Пересчёт метрик

$$\mathrm{Precision}=\frac{48}{48+49}=\frac{48}{97}\approx0{,}495.$$

$$\mathrm{Recall}=\frac{48}{48+2}=\frac{48}{50}=0{,}960.$$

$$F_1=\frac{2\cdot48}{2\cdot48+49+2}=\frac{96}{147}\approx0{,}653.$$

| Метрика | Исходный порог | Сниженный порог |
|---|---:|---:|
| Precision | 0,565 | 0,495 |
| Recall | 0,780 | 0,960 |
| F1 | 0,655 | 0,653 |

### Вывод

После снижения порога камера находит 48 из 50 нарушений вместо 39, однако число ложных срабатываний растёт с 30 до 49. Precision уменьшается: теперь только около 49,5% срабатываний обоснованны, а F1 немного снижается.

Для выбранного сценария автоматического назначения штрафов снижение порога не является улучшением: приоритетная precision стала ниже. Из двух рассмотренных вариантов предпочтителен исходный порог, хотя и его precision 0,565 недостаточно, чтобы считать систему надёжной только на основании этих результатов. Если же срабатывания направляются на ручную проверку, рост recall может быть полезен, но потребует проверки большего числа ложных тревог.
