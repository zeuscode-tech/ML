# Практическая работа №12 — Валидация и подбор гиперпараметров

## Цель работы

Построить честную схему оценки качества модели, отделить подбор гиперпараметров от итоговой оценки и сравнить Grid Search, Random Search и байесовскую оптимизацию.

## Данные

Использован датасет `o_churn_synthetic.csv` из практических работ №7 и №8.

- 3000 клиентов и 13 столбцов
- Целевая переменная: `churn`
- Доля `churn=1`: 37,13%
- Идентификатор `subscriber_code` удалён
- Категориальные признаки: `region` и `tariff`
- Пропусков нет

В начале работы выделена отложенная тестовая выборка из 600 объектов. Она не участвовала в кросс-валидации и подборе гиперпараметров.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 validation_practice.py
python3 nested_validation.py
```

## Уровень A — проверка устойчивости оценки

Оценка ROC-AUC на одиночном разбиении зависит от `random_state`:

| Разбиение | ROC-AUC |
|---|---:|
| `random_state=42` | 0.7936 |
| `random_state=7` | 0.7687 |

Разница равна 0.0248. Пятифолдовая стратифицированная кросс-валидация дала средний ROC-AUC 0.7775, стандартное отклонение 0.0149 и размах 0.0379. Разброс умеренный, но CV надёжнее одного случайного разбиения.

## Уровень B — подбор гиперпараметров

Все преобразования выполнялись внутри `Pipeline`: `OneHotEncoder`, `StandardScaler` и `LogisticRegression`. Поэтому предобработка обучалась отдельно внутри каждого фолда и утечки данных не было.

Grid Search и Random Search проверили по восемь вариантов.

| Метод | Лучший ROC-AUC CV | Время |
|---|---:|---:|
| GridSearchCV | 0.7801 | 1.0253 с |
| RandomizedSearchCV | 0.7801 | 0.1262 с |

Grid Search выбрал `C=0.01` и `class_weight="balanced"`. Random Search получил почти такое же значение `C` и то же качество за меньшее время.

### Финальная оценка на test

| Модель | Accuracy | F1 | ROC-AUC |
|---|---:|---:|---:|
| Базовая | 0.7433 | 0.6111 | 0.8062 |
| Настроенная | 0.7333 | 0.6813 | 0.8066 |

Настройка почти не изменила ROC-AUC, но повысила F1 благодаря балансировке классов. Accuracy немного снизилась, потому что модель стала чаще обнаруживать клиентов с оттоком.

## Уровень C — вложенная кросс-валидация

Во внутреннем цикле подбирались `C` и вид регуляризации. Во внешнем цикле оценивалось качество уже выбранной модели.

- Обычный GridSearchCV: ROC-AUC 0.7810
- Вложенная CV: ROC-AUC 0.7806 ± 0.0142
- Смещение обычной схемы: 0.0004

На этом датасете оптимистическое смещение оказалось очень небольшим. Вложенная CV полезна для небольших данных и большого поиска, когда требуется максимально честная оценка, но она значительно увеличивает число обучений.

## Сравнение методов поиска

| Метод | Итераций | Лучший ROC-AUC CV | Время |
|---|---:|---:|---:|
| Grid Search | 8 | 0.7810 | 0.165 с |
| Random Search | 8 | 0.7810 | 0.099 с |
| Optuna | 8 | 0.7810 | 0.306 с |

Все три метода нашли практически одинаковое решение. При таком небольшом пространстве параметров Grid Search достаточен. Преимущество Random Search и Optuna проявляется на более широких пространствах.

## Регуляризация L1 и L2

| Регуляризация | Лучший C | ROC-AUC CV | Ненулевых коэффициентов |
|---|---:|---:|---:|
| L1 | 0.10 | 0.7810 | 11 из 22 |
| L2 | 0.01 | 0.7801 | 22 из 22 |

L1 занулила половину коэффициентов и выполнила отбор признаков. L2 сохранила все признаки и только уменьшила их веса.

## Итоговый вывод

Кросс-валидация даёт более устойчивую оценку, чем одно разбиение. Гиперпараметры следует подбирать только на development-части, а test использовать один раз для итогового отчёта. Вложенная CV оправдана при малом датасете, большом поиске и высокой цене ошибки оценки; для быстрого прототипа достаточно обычного поиска и отдельного test.
